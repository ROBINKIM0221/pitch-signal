## 3.3 부상 라벨 규칙

MLB Stats API의 IL 등재 문구는 'New York Mets placed RHP Tylor Megill on the 15-day injured list. Right shoulder strain.' 같은 형식이다. 아래 규칙으로 자동 분류한 뒤, 애매한 것은 사람이 직접 판단한다.

1. **새 등재만**: 'placed … on the (7|10|15|60)-day injured list'만 쓴다('10 day'처럼 붙임표가 없는 표기 포함). 'transferred'(15일→60일 이동), 'activated', 'reinstated'는 제외한다. 7일 IL은 뇌진탕 전용이라 사례가 되지 않지만 대조군의 'IL 기록 없음' 확인에 쓴다. 사례 후보는 투수(RHP/LHP)로 등재된 기록뿐이며, 같은 투수·기준일·문구가 반복된 기록은 하나로 센다. 2021년 4월 초까지의 기록은 'placed P … on the 10 day disabled list.'처럼 옛 이름(disabled list)과 'P'로 적혀 있어 이것도 같은 등재로 읽고, 'P'의 투구하는 손은 선수 정보에서 가져온다.
2. **기준일**: 문구에 'retroactive to <날짜>'가 있으면 그 날짜, 없으면 effectiveDate(없으면 date)를 IL 기준일로 쓴다.
3. **부위**: 마침표 뒤 사유 문장에서 config.labels.arm_keywords(elbow, UCL, ulnar, Tommy John, forearm, flexor, pronator, shoulder, rotator cuff, labrum, capsule)가 있으면 팔 부상 후보, exclude_keywords(oblique, hamstring, back, finger, blister, wrist 등)만 있으면 제외다. 광배근·삼두근·이두근처럼 사례 범위(팔꿈치·어깨) 밖인 팔·몸통 근육도 exclude_keywords에 넣었다. 사유 문장이 아예 없는 등재는 부위를 알 수 없으므로 제외한다.
4. **좌우 일치**: 사유 문장에 'Right'/'Left'가 있으면(문장 어디에 있든) 그 투수의 투구하는 손(문구의 RHP/LHP, 선수 정보의 pitchHand)과 같은지 확인한다. 반대 팔이면 제외한다. 좌우가 없거나 둘 다 나오면 수기 검토로 보낸다.
5. **애매한 문구**: 두 목록 어디에도 없는 부위('arm fatigue', 'arm soreness', teres major, thoracic outlet 등), 팔 키워드와 제외 키워드가 함께 있음, 팔꿈치와 어깨가 함께 있음, 좌우 없음, 문구의 RHP/LHP와 선수 정보가 다름, 기록일과 effectiveDate가 맞지 않음(effectiveDate가 기록일보다 뒤이거나 10일 넘게 앞) → labels_review.csv로 보내 사람이 '사례/제외'와 이유를 적는다.
6. **시즌 첫 팔 부상 IL만**: 같은 투수가 같은 시즌에 팔 부상 IL에 여러 번 오르면 첫 번째만 사례로 쓴다. 이전 시즌 부상 이력은 따지지 않는다.

## 3.4 역할과 선발 판정

**선발 등판**은 경기마다 각 팀의 1회 첫 투구를 던진 투수다. Statcast에서 inning = 1이고 inning_topbot이 'Top'이면 홈 팀 투수, 'Bot'이면 원정 팀 투수가 수비하므로, 각 (game_pk, inning_topbot) 묶음에서 가장 작은 at_bat_number·pitch_number의 pitcher가 그 팀의 선발이다. **시즌 역할**은 그 시즌 등판 중 선발 등판이 과반이면 SP, 아니면 RP다. 기준선 규칙과 대조군 매칭, 결과 보고는 이 시즌 역할을 쓴다.

## 3.6 적격 등판과 투구 수 하한

'패스트볼 15구 이상'처럼 높은 고정 기준을 두면 1이닝 안팎으로 끊어 던지는 불펜 등판 대부분이 빠진다. 1이닝은 대략 15~17구이고 그중 패스트볼은 절반 안팎이기 때문이다. 짧게 자주 던지는 혹사 위험군이 빠지고, 통증으로 일찍 내려온 등판처럼 신호가 담긴 짧은 등판도 버려진다. 그래서 하한을 낮게 두고(3구), 짧은 등판은 3.8절의 가변 표본 표준화로 '덜 믿는다'. 3구 미만 등판은 품질 계산에서만 빼고 부하 채널에는 그대로 넣는다.

하한은 데이터로 확정한다. 특징별로 표본 잡음(σ_w²/n)이 등판 간 변동(σ_b²)과 같아지는 투구 수 n_min = (σ_w / σ_b)²를 개발셋에서 계산하고(단계 2.4), 핵심 3개의 n_min 중 가장 큰 값을 넘지 않는 범위에서 최종 하한을 정한다. σ_w는 등판 안 투구별 표준편차, σ_b는 등판 간 표준편차다.

**확정 (2026. 10. 5., 단계 2.4)**: 하한은 3구다. 개발셋에서 핵심 3개의 n_min은 구속 1.6구, 수직 릴리스 0.6구, 팔 각도 1.8구였다(선발만 보면 구속 2.2구. reports/tables/n_min.csv). 등판 간 변동이 커서 두세 구만 던져도 표본 잡음이 등판 간 변동보다 작다는 뜻이다. 위 기준만 보면 2구 이하도 되지만, 한 구의 추적 오류나 구종 분류 실수에 등판 평균이 크게 흔들리지 않도록 3구로 정했다. 이 하한에서 불펜 등판의 11.5%, 선발 등판의 1.7%가 품질 감시에서 빠진다(reports/tables/n_fb_share.csv).

## 3.7 기준선: 시작 구간과 움직이는 평소

투수의 평소는 시즌 중에도 조금씩 움직인다. 개발셋에서 시즌 초 평균을 평소로 고정해 두고 비교했더니, 시작 구간 직후 3등판에서는 표준화한 값의 분산이 1.2였지만 20등판 뒤에는 2.2로 커졌고 앞 등판과의 상관이 0.6이었다. 그래서 평소를 고정하지 않고 등판마다 갱신하는 **움직이는 기준선**을 쓴다. 감시하는 것은 '그 등판 직전까지의 평소로 예상한 값'과 실제 등판의 차이다.

**표 4. 기준선 규칙**

| 항목 | 규칙 |
|---|---|
| 시작 구간 — 선발 (SP) | 그 시즌 첫 8개 적격 등판. 8개를 못 채운 투수-시즌은 감시 대상에서 뺀다(직전 시즌 기록으로 대체하지 않음) |
| 시작 구간 — 불펜 (RP) | 그 시즌 첫 15개 적격 등판과 주력 패스트볼 누적 120구 중 늦은 시점까지 |
| 단위 없애기 | 특징별로 시작 구간의 '등판 안 투구별 합동 표준편차'로 나눔 (stats_core.scale_factors) |
| 투수별로 추정하는 것 | 등판 안 공분산 Σ_w = 시작 구간 등판별 표본공분산의 (n_i − 1) 가중 평균 (stats_core.phase1이 돌려주는 Sw) |
| 합동으로 추정하는 것 | 평소가 한 등판 사이에 움직이는 공분산 Σ_s와 등판마다 흔들리는 공분산 Σ_e. 투수마다 따로 추정하지 않고, 개발셋(2021~2023)에서 시작 구간이 있는 모든 투수-시즌의 적격 등판으로 역할(SP/RP)별 적률 추정을 한다. 이웃한 등판 평균의 차 d_t = x̄_t − x̄_{t−1}에 대해 Cov(d_t) = Σ_s + 2Σ_e + Σ_w(1/n_t + 1/n_{t−1}), Cov(d_t, d_{t−1}) = −Σ_e − Σ_w/n_{t−1} 인 것을 쓴다. 한 번 추정해 config_calibrated.yaml에 적고 검증셋·봉인 평가에 그대로 쓴다 |
| 양정치 보장 | Σ_e 고윳값은 0.01, Σ_s 고윳값은 0.001 이상으로 올림 (단위 없앤 값) |
| 평소 갱신 | 그 시즌 첫 적격 등판에서 출발해(예상값 = 그 등판 평균, 불확실성 = Σ_e + Σ_w/n_1) 등판마다 식 3으로 예상값과 불확실성을 갱신한다. 투구 수가 적은 등판은 덜 반영된다 |
| 정제 | 시작 구간 안에서 예상과 크게 다른 등판(예측 오차의 T² > χ²_p,0.99)은 평소 갱신에 쓰지 않는다. 감시 구간에서는 모든 등판을 반영한다 |
| 감시 시작 | 시작 구간 다음 적격 등판부터. 시작 구간과 감시는 투수-시즌마다 새로 함 |
| 구현 위치 | 시작 구간을 정하는 규칙은 src/common/baseline_window.py 하나로 만들어 부하 채널(2.5)·사례 확정(2.6)·감시(4.1)가 같이 씀. 합동 추정과 평소 갱신은 src/common/monitoring.py에 둔다(코드에서 Σ_s는 Dynamics.Q, Σ_e는 Dynamics.Se). stats_core는 고치지 않고, 등판마다 만든 Baseline(평균 = 예상값, Σ_b = 예상값의 불확실성 + Σ_e)을 outing_u에 넘긴다 |
| 비교용 | 시즌 초 평균에 계속 비교하는 고정 기준선(합동 Σ_b, 평균 추정 오차 보정)은 움직이는 기준선으로 바꾼 이유를 보여 주는 비교에서만 계산한다 (3.13.5) |

## 3.8 가변 표본 표준화와 감시 통계량 (Phase II)

등판 평균 x̄_t는 그때의 평소 L_t에 등판마다의 흔들림과 표본 잡음이 더해진 값이고(공분산 Σ_e + Σ_w/n_t), 평소는 등판 사이에 조금 움직인다(L_t = L_{t−1} + 움직임, 공분산 Σ_s). t−1번째 등판까지 보고 예상한 값을 m_t, 그 불확실성을 P_t라 하면 예측 오차 x̄_t − m_t의 공분산은 C_t다. 이를 기준으로 표준화하면 정상 상태의 u_t는 등판 길이나 시즌 중 시점과 상관없이 N(0, I)를 따르고 등판끼리 독립이다. 통계적품질관리의 가변 표본 크기 관리도를 다변량으로, 그리고 수준이 움직이는 공정으로 확장한 형태다.

```
C_t = P_t + Σ_e + Σ_w / n_t,    u_t = C_t^−1/2 (x̄_t − m_t),    T^2_t = u_t^T u_t    (식 1)
```

```
z_t = λ u_t + (1 − λ) z_t−1,    Q_t = (2 − λ)/λ · z_t^T z_t    (식 2)
```

```
K_t = P_t C_t^−1,    m_t+1 = m_t + K_t (x̄_t − m_t),    P_t+1 = (I − K_t) P_t + Σ_s    (식 3)
```

T²는 예상에서 한 번에 크게 벗어난 등판을, MEWMA는 여러 등판에 걸쳐 같은 방향으로 예상을 벗어나는 흐름, 곧 평소가 움직이는 보통 속도보다 빠른 변화를 잡는다. 평소가 움직이는 보통 속도보다 느린 변화는 정상 변동과 구별하지 않는다. **경보 규칙**은 'T²_t > χ²_p, 0.999 또는 Q_t > h'이고, **경보 직후 z를 0으로 되돌린다**. 경보 하나를 한 번의 사건으로 세서, 정상 상태 오경보율이 100/ARL0가 되게 하기 위해서다. 구현은 stats_core.outing_u, monitor를 그대로 쓴다.

**신호 두 가지 (2026. 10. 6. 결정)**. 품질 채널의 경보는 둘로 나누어 따로 표시하며, 서로 독립적으로 돈다(한쪽 경보가 다른 쪽 통계량을 되돌리지 않음).

- **구속 하락 신호 (주 신호)**: 구속 하나(p = 1)로 같은 움직이는 기준선과 표준화를 적용한 예측 오차 u^v_t에 한 방향 EWMA를 쓴다. z^v_t = λ u^v_t + (1 − λ) z^v_t−1, s_t = √((2 − λ)/λ) · z^v_t (정상 상태면 s_t ~ N(0, 1)). **경보 규칙**은 's_t < −k'로, 구속이 예상보다 낮은 쪽으로 이어질 때만 울리며 경보 직후 z^v를 0으로 되돌린다. **구속 하락 지수** D_t = −s_t / k(되돌리기 전 값)는 1 이상이면 경보이고, 화면에는 이 지수를 보여 준다.
- **폼 변화 신호 (보조)**: 식 1~2의 다변량 규칙 'T²_t > T² 한계 또는 Q_t > h' 그대로. 세 특징(구속·수직 릴리스·팔 각도)이 어느 방향으로든 평소와 달라지면 울린다. **폼 변화 지수** = max(T²_t / T² 한계, Q_t / h).

이렇게 나눈 이유: 개발셋에서 부상 전 관찰 창에 일관되게 나타난 변화는 구속 하락뿐이었고(평균 0.1~0.2 mph), 수직 릴리스·팔 각도·회전수·익스텐션에는 차이가 없었다. 방향을 가리지 않는 다변량 규칙은 신호가 없는 방향에 오경보 몫을 쓰게 되어 부상 판별력이 거의 없었다(변경 기록 참고). 폼 변화 신호는 부상 전조로 주장하지 않고, '무엇이 달라졌는지'를 3.10절의 분해와 함께 알려 주는 기능으로 둔다.

이 표준화가 필요한 이유는 가상 수치 시뮬레이션으로 확인했다(표 5). 분산 하나로 모든 등판을 같게 처리하면, 투구는 그대로인데 기용만 짧아져도 경보가 두 배로 늘어 품질 경보가 '짧게 쓰였다'에 반응한다. 가변 표본 표준화는 탐지력을 키우는 방법이 아니라 **오경보율 보장을 등판 길이와 무관하게 지키는 방법**이다.

## 3.9 오경보 설계 (ARL)

목표는 **신호마다 정상 상태에서 평균 100등판에 한 번 경보(ARL0 = 100)**다. 선발은 한 시즌 약 30등판이라 약 3시즌에 한 번, 불펜은 약 60등판이라 약 1.7시즌에 한 번꼴이며, 두 신호를 합치면 최대 두 배다. 결과는 100등판당과 시즌당을 함께 보고한다. 관리한계(구속 하락 신호의 k, 폼 변화 신호의 T² 한계와 h)는 두 번에 걸쳐 정한다.

1. **이론 보정**: 표준화된 u는 정상 상태에서 N(0, I)이므로 h는 특징 수 p와 λ에만 의존하고, 선발·불펜에 같은 h를 쓸 수 있다. 표준정규 난수 시퀀스로 'T² 또는 MEWMA' 규칙의 평균 런 길이를 계산해 ARL0 = 100이 되는 h를 찾는다(stats_core.calibrate_h). 참고값은 표 6와 같다. 같은 설정이면 다시 계산한 값도 이와 거의 같아야 한다. 구속 하락 신호의 한 방향 EWMA 한계 k도 같은 방식(표준정규 시퀀스, ARL0 = 100)으로 찾으며 참고값은 λ 0.1 / 0.2 / 0.3에서 1.73 / 2.01 / 2.13이다.
2. **실측 보정**: 합동 추정한 Σ_s·Σ_e는 평균적으로만 맞고(투수마다 실제 변동이 다름) 등판 평균의 분포는 정규분포보다 꼬리가 두꺼우므로, 실측 오경보율은 이론값과 조금 다르다(개발셋 감시 등판 전체에서 이론 한계로 100등판당 불펜 0.7회, 선발 2.7회). 개발셋 대조군의 실측 오경보율이 100등판당 1.0이 되도록 한계를 다시 찾는다. **신호마다, 그리고 선발·불펜 따로** 맞춘다(2026. 10. 6. 결정). 구속 하락 신호는 k를, 폼 변화 신호는 T² 한계와 h를 찾으며 이 실측값이 최종값이다. T² 한계는 χ²_p,0.999에서 시작하되, T²만으로 그 역할 대조군의 실측 오경보가 100등판당 0.5를 넘으면 실측 0.5가 되는 값(대조군 T²의 상위 0.5% 값)으로 올린 뒤 h를 맞춘다. 실측 한계는 시퀀스가 시즌마다 0에서 새로 시작하고 u의 분산이 1보다 조금 작아 이론값보다 낮게 나올 수 있다. 최종 k·h·T² 한계는 config.yaml이 아니라 config_calibrated.yaml에 기록한다.
3. **λ**: 두 신호 모두 λ = 0.2로 고정한다(2026. 10. 6. 결정). 개발셋에서 0.1·0.2·0.3의 구속 하락 지수 일치도가 0.601·0.604·0.604로 같아 고르는 절차를 없앴다. 0.1과 0.3은 민감도 분석으로 보고한다. 이전에 두었던 제안 방식 후보(기본형·결합형)와 '개발셋 탐지율로 선택' 규칙은 폐기했다.
4. **탐지 성능 계산(ARL1)**: 표준화 단위로 0.5·1.0·1.5 SD 이동을 넣었을 때 몇 등판 만에 잡는지 계산해 '설계 성능표'로 제시한다(stats_core.arl1).

## 3.10 경보 원인 분해 (MYT, 확장 1)

폼 변화 신호가 울리면 MYT 분해로 T²를 특징별 기여로 나눈다. 구속 하락 신호의 경보 카드는 구속 하락 지수와 최근 등판의 구속 예측 오차(mph)를 보여 준다. 원래 단위의 등판 평균 x̄_t, 예상값 m_t, 공분산 C_t를 쓰며, 특징 j의 무조건 항 T²_j = (x̄_t,j − m_t,j)² / C_t,jj와 조건부 항(다른 특징을 고려한 뒤 남는 이탈)을 계산한다. 경보 카드에는 기여가 큰 상위 2개 특징과 부호 있는 표준화 이탈(예: '수직 릴리스 −1.8σ, 구속 −1.2σ'), 그리고 MEWMA가 울린 경우 z_t의 성분별 크기를 함께 보여 준다. 시간이 모자라면 표준화 이탈 크기 순위만으로 대신한다.

## 3.13 검증 설계

### 3.13.1 가설

- **H1 (주 가설)** 검증셋에서 관찰 창의 구속 하락 지수(창 안 5등판의 최댓값)는 사례가 짝지은 대조군보다 크다. 판정은 3.13.4의 짝지은 일치도.
- **H2** 구속 하락 신호로 탐지된 사례에서 첫 경보는 IL 등재보다 중앙값 2등판 이상 먼저 울린다.
- **H3** 2026 봉인 평가에서 두 신호 각각의 실측 오경보율은 설계값(100등판당 1.0)의 2배 이내다.
- **H4 (보조)** 불펜 사례의 관찰 창에는 대조군보다 부하 채널 표시가 더 자주 나타난다.
- **보조 분석** 경보 기준에서의 탐지율과 대조군 창 내 경보 비율(두 신호 각각, 차이의 95% 신뢰구간), 같은 오경보율(100등판당 1회)에서 구속 하락 신호와 B1~B4의 탐지율 비교, 폼 변화 지수의 일치도. 우열을 가설로 두지 않고 결과를 그대로 보고한다.

**표 11. 평가 지표**

| 지표 | 정의 |
|---|---|
| 창 지수 | 관찰 창 5등판의 구속 하락 지수(또는 폼 변화 지수)의 최댓값. 1 이상이면 창 안에 경보가 있었다는 뜻 |

### 3.13.4 통계 검정

H1은 사례마다 c = (그 사례의 구속 하락 창 지수가 각 대조군의 창 지수보다 큰 비율, 같으면 0.5)을 구하고 그 평균을 짝지은 일치도라 한다. 사례 단위 부트스트랩(사례와 그 대조군을 함께 재표집, 2,000회)으로 일치도의 95% 신뢰구간을 계산해 하한이 0.5보다 크면 지지로 판정한다. 대조군이 없는 사례는 H1에서 빼고 그 수를 보고한다. 보조 분석의 탐지율 차이(사례의 창 안 경보 비율 − 대조군의 창 내 경보 비율)도 같은 부트스트랩으로 95% 신뢰구간을 낸다. 비교 분석에서는 방식 간 탐지율 차이의 95% 신뢰구간을 같은 부트스트랩으로 계산하고, 사례별 탐지 여부를 제안 방식과 각 비교 대상 사이에 McNemar 정확 검정으로 비교하며, 비교가 4개이므로 Holm 보정을 한다. H4는 불펜 사례와 그 대조군의 '관찰 창 안 부하 표시 여부'를 짝지은 자료로 보고 McNemar 검정으로 확인한다.

### 3.13.5 민감도 분석과 하위 그룹

1. 평활 상수 λ: 0.1, 0.3 (고정값 0.2와 비교) / 선발 기준선 길이: 6, 8, 10등판

3. 등판 길이 처리: 분산 하나로 처리한 경우와 가변 표본 표준화의 투구 수 구간별 실측 오경보율 (표 5의 실제 데이터판)
4. 투구 수 보정 그래프: 대조군에서 패스트볼 수 구간(3~5, 6~9, 10~15, 16구 이상)별 u의 분산이 1 근처인지
5. 합의 규칙의 오경보율·탐지율
6. 실패 분석: 놓친 사례의 공통점(급성 부상, 등판 간격, 역할 변화, 기준선 직후 부상)

8. 기준선 방식: 고정 기준선(시즌 초 평균에 계속 비교)과 움직이는 기준선의 u 분산(투구 수 구간별, 시작 구간 뒤 등판 수별), 앞 등판과의 상관, 실측 오경보율 비교 (개발셋). 투수별로 Σ_b를 추정하는 원 설계의 문제는 tools/sim_small_baseline.py로 보인다

### 3.13.7 결과가 기대보다 약할 때 (플랜 B)

제안 방식이 비교 대상보다 탐지율이 높지 않을 수도 있다. 결과를 숨기지 않고 다음 순서로 가치를 재정의한다.

1. **오경보 통제의 가치**: 탐지율이 비슷해도 실측 오경보율이 설계값에 가깝게, 등판 길이와 무관하게 유지된다면 '현장에서 믿고 쓸 수 있는 기준'이라는 가치가 있다(H3, 3.8절).
2. **다변량의 가치**: 폼 변화 신호가 부상 전조로 입증되지 않더라도, 어떤 특징이 어느 방향으로 달라졌는지(3.10절)를 알려 주는 점검 도구로서의 가치를 보인다.
3. **하위 그룹 강점**: 선발·팔꿈치처럼 강점이 있는 집단을 찾아 적용 범위를 분명히 한다.
4. **설명 가능성**: 같은 성능이라도 '왜 울렸는지' 보여 주는 점을 강조한다.
5. **고교 모듈 비중 확대**: 한국 적용과 전국체전 실증 서사의 비중을 높인다.

### 3.14.3 규정 엔진과 누적 부하

- **KBSA 규정 판정** (src/core/kbsa_rules.check_violations): 하루 105구 초과, 투구 수별 의무 휴식일 미준수(d일에 휴식 r일이면 다음 등판 가능일은 d + r + 1일), 3일 연속 등판. 같은 날 두 경기는 합산한다.
- **ACWR** (kbsa_rules.acwr): 최근 7일 합 ÷ (직전 21일 합 / 3). 직전 21일이 모두 그 학교의 기록 수집 기간이 아니면 '계산 불가'로 표시한다. 기록이 비어 만성 부하가 과소 추정되는 것을 막기 위해서다.
- **3일·7일 누적 투구 수**와 **해외 규정 시뮬레이션**: 일본 '1주 500구'(kbsa_rules.window_limit_violations). 대만·캐나다 기준은 원출처를 확인해 config.yaml에 채운 뒤에만 계산한다.
- **규정 위반과 누적 부하 경보는 섞지 않는다.** 현황판에서 신호등 두 개(규정 준수, 누적 부하)로 따로 보여 준다.

## 3.15 KBO 사례 연구 명세 (확장 2)

1. **대상**: 팔 부상이고 2025 KBO 기록으로 기준선을 잡을 수 있는 요니 치리노스(LG, 팔꿈치), 미치 화이트(SSG, 어깨), 아리엘 후라도(삼성, 어깨). 오웬 화이트(한화)는 수비 중 햄스트링 파열이라 투구 신호와 무관하고 개막 직후 다쳐 기준선도 없으므로 '대응' 사례로만 쓴다.
2. **신호**: 공개 코드로 2025~2026 투구별 구속을 모아, 구속 하나로 3.8절의 가변 표본 EWMA(p = 1)를 그린다. 기준선은 2025 시즌 마지막 8개 선발 등판이다. KBO 공개 데이터에는 릴리스 높이·팔 각도가 없으므로 '구단 내부 트래킹 데이터를 넣으면 전체 버전이 동작한다'고 설명한다.
3. **대응**: 말소일부터 결정일까지의 기간(실행기획서 2.5절 표)과 대체 선수의 경과를 같은 타임라인에 표시한다. 대체 후보 추천 모델은 만들지 않고 로드맵 2단계로 둔다.
4. **해석 원칙**: 신호가 있으면 '말소 전 몇 등판부터 평소 범위를 벗어났다', 없으면 '구속만으로는 신호가 보이지 않았다'고 그대로 쓴다. 관리한계는 MLB 개발셋에서 정한 이론 h를 그대로 쓰고 사례에 맞춰 바꾸지 않는다.

## 3.16 트리플A 외부 검증 명세 (확장 4, 선택)

Savant 마이너리그 검색으로 트리플A 투구 데이터를 받을 수 있는 기간과 열을 확인하고, MLB Stats API transactions(sportId = 11)로 트리플A IL 기록을 받을 수 있는지 확인한다. 두 가지가 모두 되고 팔 부상 사례가 30건 이상이면, MLB에서 확정한 설정(하한, λ, 실측 h)을 **바꾸지 않고** 그대로 적용해 탐지율과 오경보율을 보고한다. 하나라도 안 되면 '확인한 결과 실행 불가'와 이유를 기록하고 마친다.

## 3.18 기술 세부 기본값 (단계 3.1에서 검토)

아래 값은 대화에서 따로 정하지 않은 기술 세부다. 기본값으로 config.yaml에 넣어 두었고, **평가 계획서를 쓰는 단계 3.1에서 검토해 바꿀 수 있다.** 고정(단계 3.2) 뒤에는 바꾸지 않는다.

**표 16. 기술 세부 기본값**

| 항목 | 기본값 | 바꾸면 생기는 일 |
|---|---|---|
| 기준선 방식 | 움직이는 기준선. Σ_s·Σ_e는 개발셋 역할별 합동 추정 | 시즌 초 평균에 고정하면 평소가 움직이는 만큼 오경보가 늘어 개발셋에서 100등판당 약 19회가 됨. 투수별로 공분산을 추정하면 등판 수가 적어 더 나빠짐 |
| T² 경보 한계 | χ²_p, 0.999 (T² 단독 개발셋 실측 오경보가 100등판당 0.5를 넘으면 실측 0.5가 되는 값으로 올림) | 낮추면 한 번에 큰 이탈을 더 잘 잡지만, 같은 오경보율을 맞추느라 MEWMA 한계가 높아져 작은 이동을 늦게 잡음 |
| 경보 후 재시작 | z를 0으로 (신호마다 따로) | 재시작하지 않으면 경보가 연달아 울려 오경보율 계산이 부풀려짐 |
| λ | 0.2 고정 (두 신호) | 개발셋에서 0.1·0.3과 차이 없음. 민감도 분석으로 보고 |
| 관리한계 보정 단위 | 신호마다, 선발·불펜 따로 100등판당 1.0 | 합치면 폼 변화 신호 오경보가 선발 1.7 / 불펜 0.65로 벌어짐 |
| 기준선 정제 기준 | 시작 구간에서 예측 오차의 T² > χ²_p,0.99인 등판은 평소 갱신에서 제외 | 느슨하게 하면 이상 등판이 평소를 끌고 감 |
| 고윳값 하한 | Σ_e 0.01, Σ_s 0.001 (단위 없앤 값, 합동 추정값에 적용) | 크게 하면 전반적으로 덜 민감해짐 |
| 선발 기준선 부족 시 | 제외 (직전 시즌으로 대체하지 않음) | 대체하면 시즌 초 부상 사례 일부를 살릴 수 있지만 사례와 대조군의 기준선이 달라짐 |
| B2 WHIP 처리 | 아웃 0개 → 1개 하한, 99% 윈저화 | 처리하지 않으면 무한대 값이 생김 |
| B3 수축 | 기준선 대각으로 50% | 수축하지 않으면 4개 등판 공분산이 불안정 |
| 부트스트랩 반복 · seed | 2,000회 · 2026 | 늘리면 신뢰구간이 조금 안정, 시간 증가 |
| 트래킹 결측 제외 기준 | 핵심 특징 결측 등판 20% 초과 | 느슨하게 하면 잡음 증가 |
